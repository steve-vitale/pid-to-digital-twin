# Where the selected workflows generalize: the corpus matrix

Generated by `scripts/corpus_matrix.py` from `out/generalization/matrix.json`; the inputs are registered in
`data/corpus.json`. Do not edit by hand: `python scripts/corpus_matrix.py` re-runs it and
`python scripts/corpus_matrix.py --check` confirms this page matches the JSON.

These eight workflows cover tracing, scorer controls, intake/report, loop audit, exports, historian bands, DEXPI conversion and pipe topology. They do not cover every tool: point mapping, applying reviews, the question engine, impact estimates and live replay have their own feature tests and examples. Each cell runs one selected workflow on one registered public input it applies to, with no model and no network. **pass** and **FAIL** use the criterion stated for each row below; each was fixed before that row's first run unless the row says otherwise. **n/a** means the tool can't apply to that input (the reason is given); **needs data** names the fetch command for an input that isn't cached (a clean clone has the committed inputs only); **needs deps** means a module from `requirements.txt` is missing. A FAIL is a finding, not an error in the matrix. **(self-generated)** marks an input this repository generated from its own process model (the TE and Bayer sheets): a pass there is circular evidence, showing the tool agrees with the generator, not that it carries over to someone else's drawing. **(agent-made key)** marks a cell scored against an answer key a coding agent made (data/agent_keys/, a first pass no person has reviewed): weaker evidence than a hand key, kept apart from the human-keyed results and never counted as an independent source family.

Rows are not always run together, so each cell records its own run time and a hash of the tool files it exercised; `--check` fails when a tool has changed since its cells ran.
