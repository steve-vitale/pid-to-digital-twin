## Extract: Read a drawing or a structured file into a draft asset model

<a id="drawing-to-bundle"></a>
### A P&ID image to a draft asset model and review bundle

Example review: **reviewed example**

**Why it matters:** Retyping drawings into asset lists takes manual effort in historian, HMI and digital twin projects. A draft turns some of that typing into checking; the time saved has not been measured.

**Inputs:** One P&ID as a PNG; a model subscription (or the committed example)

**Outputs:** Extracted symbols, tags and links as a draft model, a review sheet ranked for checking, Ignition tags and PI staging

**Time:** 88 s of commands on one new sheet (sheet 8), measured once; sheet 0's recorded run took 75 s plus 1 s; review time not measured

- **Tools:** `run_extraction.py`, `trace_connections.py`, `scan_cleanup.py`, `import_site_drawing.py`, `site_extraction_workflow.py`

### A DEXPI P&ID file to the same bundle, with no model reading

Example review: **reviewed example**

**Why it matters:** A CAD export already represents symbols and connections as data. Reading supported DEXPI content directly avoids a visual model-reading step; conversion limits and omissions still need review.

**Outputs:** The same bundle with no model reading: tags are the drawn label text, and links are the drawn connections, undirected, with each pipe tee expanded into pairwise links

**Time:** Seconds once the sheets are prepared

- **Tools:** `dexpi_to_twin.py`

<a id="graph-export"></a>
### The model as an open graph of sourced claims

Example review: **reviewed example**

**Why it matters:** A plant model is a web of relationships: this transmitter measures that line, this controller moves that valve. Kept as a graph, it answers questions a flat tag list can't, like what a valve's failure affects or which instruments nobody has checked, and other systems can load it without retyping.

**Inputs:** Any model this repository produces

**Outputs:** One open JSON graph: assets, typed links in three layers (pipe segments and tees, line networks, and network pairs), every attribute with its source and status; plus a smaller core profile (identity, settings, impact relations and sources) for loading into another system, with everything it leaves out counted

**Time:** Seconds

- **Tools:** `graph_export.py`, `line_layers.py`
- **How to use it:** [GRAPH_EXPORT.md](../docs/GRAPH_EXPORT.md)

<a id="statement-review"></a>
### Every output as plain statements, checked against its source

Example review: **reviewed example**

**Why it matters:** "Does this look right?" has no answer you can track. A sampled review of plain sentences against their sources gives an error rate for each kind of statement, and keeps 'matches the drawing' apart from 'true in the plant', which only someone who knows the unit can say.

**Inputs:** A graph export (twin-graph-1), plus the sheet image or report PDF its sources cite

**Outputs:** A stratified sample of plain sentences, each beside its drawing crop or report page, with two separate verdict columns; an error rate with a 95% interval; and the verdicts written back into the graph as dated events

**Time:** Seconds to render; review time per statement not yet measured

- **Tools:** `statements.py`
- **How to use it:** [STATEMENT_REVIEW.md](../docs/STATEMENT_REVIEW.md)
