# Whole-process Overview and instrumented unit detail (local prototype)

Built from `operator-screens` at `20aa7cd32ea0ee793394f063bbdf8234f5a12590`, following an earlier three-unit
prototype checkpoint that was not published separately.
Later imported into a disposable Ignition gateway; see journal entry 38 and the [native acceptance page](IGNITION_ACCEPTANCE.md). No deployment is claimed.

## Navigation and process coverage

`/` now opens the full six-unit process Overview. `/mimic` is a compatibility alias to identical content, with
Overview selected. There is no competing Mimic tab. Every shared header uses the same ordered tabs: Overview,
Feed, Reactor, Condenser, Separator, Compressor, Stripper, Alarms, Drawings. The reference `/schematic` remains
available from Overview. This tab order is a navigation convention for a branched/recycling process, not a claim
that all equipment lies in one serial train.

The compact 1600 × 930 Overview shows 21 essential readings alongside all six modeled units and all 13 stream directions (verified against the simulator source), including recycle,
stripper overhead, purge, external feeds and product boundary. BL means model boundary. Click equipment or a
unit tab to drill down. Unit pages link back to Overview and directly to modeled neighboring equipment.
Stream cards identify stream ID, name, source/destination and every currently mapped scalar boundary reading;
stream boundaries without a mapped instrument explicitly say so. Utility tags are identified separately:
the source model has no utility stream endpoints, so no utility piping or direction is invented.

## Deliberate Overview selection

- Feed: FT-101/102/103 show all three feeds actually owned by U-100. FT-104 belongs to C-101/S4 and stays there.
- Reactor: PT-107/TT-109 show constrained condition, LT-108 inventory, FT-106 throughput. TT-121/TV-121 cooling context is on detail. SC-212 is explicitly unavailable on detail.
- Condenser: only TT-122 (cooling-water outlet) and FV-117 are mapped, the two tags the source assigns to it. No process pressure,
  temperature or level is substituted for the missing condenser instrumentation.
- Separator: PT-113/TT-111 condition, LT-112 inventory, FT-114 throughput, FT-110 purge; LV-112, FV-110 and the purge analyzer are on detail.
- Compressor: FT-105 recycle, JT-120 work and FV-105 recorded output give recycle context.
- Stripper: PT-116/TT-118 condition, LT-115 inventory, FT-117 product; FT-104 feed and FT-119 steam input are on detail.

These are reviewable display choices, not validated operating envelopes or new safety limits. Detail screens
include all modeled tags plus the separately represented, source-indexed analyzer components. See
[INSTRUMENT_COVERAGE.md](INSTRUMENT_COVERAGE.md) for the count, ownership, component and boundary inventory.

## What unit detail adds

Each unit has an equipment-specific rendering, dynamic level where a level tag exists, local mapped boundary
readings, selected condition readouts, and all available tag rows. Rows include the recorded reading, existing
normal band and alarm limits, existing State text, 30-minute history and source-review metadata. Final elements
also get recorded-output gauges. Analyzer components have their own source-indexed readings, bands and history;
original scalar paths remain compatible. SC-212 remains not connected because XMV12 is absent from the replay.

UNKNOWN is explicit for bad-quality, missing, nonnumeric and nonfinite readings. Level fill becomes hatched;
output gauges hide fill. A valid zero remains zero. Percentage graphics clamp to 0–100, retaining off-scale
numbers in the overview. Readout/state bindings are independently quality-checked. Native history retains the
existing raw-point / ignore-bad-quality configuration; no zero-filled gap is invented by the preview.

Unit ownership, stream endpoints and flow directions are verified against the simulator source
(`out/te_topology_check.md`, journal entry 42); equipment geometry, tap positions and pipe routes are not, because
the source has none. Stream arrows are static source-verified directions, not measured flow. Level percentages are
not calculated vessel volumes. XMV outputs are not measured valve positions. TT-122 is the condenser cooling-water
outlet temperature (the source's "separator" label reflects where the simulator books condenser duty). PT-116
ownership is unresolved in the source and is flagged on the stripper page. No responsive physics, closed-loop controls, new alarms or operator acceptance are implied.

## Generate and inspect locally

From the repository root:

    python scripts/fetch_te_data.py
    python scripts/preview_mimic.py
    python scripts/test_process_mimic.py
    python scripts/run_tests.py

`fetch_te_data.py` checks both replay files against the repository's recorded SHA-256 hashes. The standalone
offline preview generated by the command above offers normal sample 0, fault-6 sample 258, and an explicitly bad-quality fixture.
It evaluates the same transform source as the export, but is **not a Perspective runtime**. Preview state values
are recomputed from the committed normal bands and alarm limits. Real Perspective uses the existing gateway State
tags instead. Overview, six unit pages, equipment/neighbor links and browser hash Back/Forward routes are implemented in the standalone preview. Alarm/drawing/schematic links clearly state that those destinations require the gateway export. Native history and review metadata are labeled as unavailable in the offline rendering rather than fabricated.

Generated previews and image/project exports are not included in this publication.
Generate approximate static snapshots with `python scripts/render_mimic_snapshots.py` (requires Inkscape). These files are clearly
labeled **offline SVG renders, not gateway screenshots**. The rendering tool approximates label wrapping; it does
not prove browser layout or Perspective schema compatibility.

## Verification and limits

The 19 focused offline controls cover existing tag-path resolution including UDT members, unique component names, supported
local component structure, hidden tags, read-only navigation-only events, deterministic generation, unchanged
process model, original stream IDs, summary count quality and independent PV/State quality, explicit unmapped agitator behavior, quality handling and SVG parseability at
zero, midscale, fullscale, off-scale, missing, nonnumeric and nonfinite inputs. Alignment, nonoverlapping columns, canvas bounds, and value/unit pairing also have regression tests. They are included in the aggregate
repository test runner.

All eight aggregate test scripts passed locally after installing the missing asyncua 2.1.0 and
opencv-python-headless 5.0.0.93 dependencies into an isolated temporary dependency directory. To run checks in a fresh environment
with the repository requirements installed:

    python scripts/run_tests.py

The original pinned requirements were not changed. Transitive packages in the temporary target include numpy 2.5.3
and cryptography 50.0.2, rather than the versions pinned in the repository's full requirements file; this is not an
exact-lockfile environment reproduction.

Update 2026-10-12/13: the first native import (disposable Ignition 8.3.10 container) showed that every script
transform written by this work failed to parse in Perspective (unindented bodies), so every reading showed `null`.
The offline harness above had re-indented the code before running it. Both are fixed, and the overview and unit
pages then passed the native browser contract (journal entry 38). The paragraph below is the original
pre-import status.

Not run: Ignition import, actual Perspective/Jython transform execution, live OPC bindings, browser interaction,
gateway verifier, operations review. Chromium launch failed because this execution environment disallows the
required socket creation, including after escalation. No existing gateway verification receipt covers this change.
Before deploying, import into an authorized development gateway and check native schema, all bindings, quality

does not authorize that import or any public action.

## Spatial unit correction

Unit pages now begin with compact annotated diagrams; full inventory/history are secondary below. Plain-language
names and value/unit pairs are placed by mapped stream or approximate vessel region, with dashed association leaders.
Analyzer components sit together by the mapped sample stream. Unmodeled utility endpoints and disputed ownership
remain explicit. The original process model is unchanged. See journal entry 23 for the published schematic source.
The purge and TT-122 discrepancies noted there were settled against the simulator source in journal entry 42.

`data/te_display_layout.json` is additive presentation configuration. `unit_context(..., layout=...)` accepts another
validated layout for the existing model shape. `scripts/display_contract.py` validates reference/evidence geometry;
unknown flow direction does not draw arrows. TE streams carry an explicit `direction`, each verified against the simulator source; the former direction adapter is gone. The synthetic
water-utility fixture demonstrates the same unit renderer with unfamiliar IDs, mixed units and absent point mappings;
it is not evidence of majority-plant coverage. Overview, replay and gateway/export assumptions remain TE-specific.

Snapshots now cover Overview and all six unit pages for normal, fault and bad quality, using equipment names as
prefixes (`feed`, `reactor`, `condenser`, `separator`, `compressor`, `stripper`). No native browser/gateway validation
is implied by these expanded static checks.
