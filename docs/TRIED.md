# What was tried, and what wasn't

Generated by `scripts/attempts_ledger.py` from `data/attempts.json`; edit the ledger, not this page. How this project tuned each function: what was tried, what happened, what was kept or rejected, and what has not been tried. Every entry cites the document it comes from; numbers are quoted as the sources state them. Dates are the journal's own where it gives one; where the text gives none (entries 1-21, the development sweeps), the date is the day the commit that recorded the work was made.

Read this before tuning anything: if a variant is listed as rejected, the number that rejected it is here; if an idea is under *Not tried yet*, nobody has measured it, whatever its absence from the code suggests. Completed ideas are retained separately with their evidence.

**Verdicts**

- **kept**: adopted, and still how the project works.
- **rejected**: tried and measured, then not adopted.
- **superseded**: adopted at the time, later replaced (the replacement is usually the next row).
- **inconclusive**: measured, but no decision rests on it: a measurement round, a diagnostic, or a difference within noise.

**Idea status** marks each idea as *rejected-untested* (rejected on reasoning, never run); *not-done* (named in the docs as a next step or a gap, not done); *open-question* (a question the sources leave open); *done* (completed later; retained with its evidence). An idea rejected after it was measured is an attempt, not a not-tried item.

**Single runs are flagged.** A *runs* cell that starts with 1 is one run (per tool, per holdout or per sweep step). Where a model call is involved, that number carries run-to-run noise: five runs of the declared method moved with a standard deviation of 1.4-1.9 review-load points, more than the ~1 point assumed earlier. Read a small single-run difference as a tie. Deterministic code (scorer controls, generators, checks) repeats exactly, but a single run still shows one input, not a sample.
