# Keep one source revision reviewable

Start with an existing description and authored model. Review a source note, then show what happens when that
note changes. This fictional pump example connects the question engine, context register and selected snapshot
MCP into one maintenance journey. It uses their existing behavior; it does not add a company governance service.

All notes, equipment, actors, dates and decisions are invented training fixtures. The example demonstrates
software accounting. No engineer, recipient, company, Copilot tenant or operating plant has accepted the result.

Read the [worked source-change review](worked/CHANGE-REVIEW.md), then the [fictional handoff](worked/HANDOFF.md)
before running anything. That compact worked packet retains both original source revisions, one selected catalog,
the full current and stale context history, and the generated E1 findings. Its source and selected packet bytes
are pinned through Git by this example's local attributes. Keep the whole `worked/` folder when handing it on.
The raw catalog kept there has its own identity; line-ending-normalized copies are different bytes.

From the repository root, run the standard-library portion into a new folder:

```sh
python examples/pump-revision/reproduce.py --out out/pump-revision
```

Open `out/pump-revision/CHANGE-REVIEW.md`, then `HANDOFF.md`. The folder retains the original records, selected
catalog, native input models, generated findings, full contexts and command/check receipts. Keep those originals
with the result when handing it to another engineer. The output folder must be new; earlier runs are preserved.
The script respects your TEMP/TMP settings and the operating system defaults. Fresh outputs record their own
actual hashes and the catalog selected from this checkout; they need not match the historical worked packet.
The recorded Git-byte review was performed on Windows with autocrlf true and false. Repository CI is configured
to run generation and selected stdio readback on Linux; inspect the current run before relying on it. macOS and
company-scale deployment have not been tested.

| Step | What you can inspect |
|---|---|
| First source answer | Pump note A supports a partial source answer; the separate tank note supports a source answer. Both keep plant truth unknown. |
| Revised source | The pump note changes from `12 m` to `12 kPa`. These are deliberately incompatible raw units; nothing is converted or accepted as an engineering correction. |
| Explicit refresh | The pump's earlier answer becomes stale. The independent tank answer stays current. Complete earlier evidence, decisions and ownership remain in history. |
| Fresh source review | A new prepared sheet binds a new partial source answer to revision B. Reusing the old sheet refuses before output mutation. |
| Unresolved investigation | The actual generated `E1@P-1` finding stays unanswered. Zero, false, null, unknown and an explicitly unmapped bearing note remain visible. |
| Handoff | A worked fictional brief names exact source/model/graph/context/catalog hashes and what the next engineer must resolve. Receiving ownership and company acceptance remain unassigned. |

`PUMP-NOTE@P-1` and `TANK-SERVICE@TK-1` are visibly authored source questions. `E1@P-1` is freshly generated by
the existing catalog engine; its complete finding is retained. A source match does not answer its operating-basis
requests. The geometry and topology are unchanged, so an unchanged drawing is not presented as a design correction.

The model deliberately omits the raw bearing note. Its original text and fixture omission accounting are kept
in `source-records/`; no native mapping is inferred. This example's `unmapped.json` is teaching data, not a general
source-capture schema. Stable engineering IDs apply only to this controlled fixture.

To exercise actual readback, use an approved environment with the optional pinned dependencies in
`requirements-mcp.txt`, then run against the same completed folder:

```sh
python examples/pump-revision/reproduce.py --out out/pump-revision --sdk-only
```

This opens two local stdio sessions and no network port. The first server keeps serving exact A records after
only its disposable selected files are replaced by B. After an explicit restart, the new server serves exact B
records, including retained A history. Both mixed graph/context combinations refuse at startup. Complete nodes,
relations, questions, context, ownership and paginated decisions are compared with the selected files.

Snapshot MCP reads the selected packet; it does not fetch original notes or observe the plant. Keep original
source records alongside that packet. Structural checks ran here; physical and safety checks did not run.
An actual engineer/recipient exercise remains [external acceptance work](../../docs/ACCEPTANCE.md).
