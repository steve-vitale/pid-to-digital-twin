# MetroPT-3 context packet acceptance

Declared 2026-10-30, after discovery read the dataset description and the first three measurement records.
The description's population/rate, duplicate failure numbers and ambiguous maintenance note were already seen.
This is development of the context workflow on an existing historian corpus family, not a held-out test or new
global source family. No anomaly method, matrix criterion, historical score or plant model will be tuned here.

1. Use the original description PDF and measurement CSV from the pinned UCI ZIP. Preserve original bytes,
   names, sizes and hashes; keep the originals in the ignored cache. Preparation is offline and never downloads
   implicitly. An explicit existing fetch command prepares a clean clone. Missing or changed originals refuse.
2. The identity model is an explicitly authored packet scope for the described APU, not a known serial number,
   current train or verified physical asset identity. Add no invented piping, signal ownership or deployed state.
3. Bind every proposed answer to an exact PDF page/table row or CSV physical line and raw source hash. Keep the
   source's `DV_eletric` spelling, duplicate `#1` numbers and `30Apr` note. Distinguish internal locator ordinals
   from the source's printed report numbers. Do not repair them by inference.
4. Separate the documentation's acquisition/population claims from observed released-file facts. The first
   timestamp gaps are observations on those records only, not a universal period. A mismatch in scope needs
   clarification; it must not become an invented simultaneous contradiction or an automatic resampling rule.
5. Keep the description's signal meanings separate from recorded values. A recorded electrical flag, near-zero
   motor current or pressure does not establish a unique operating mode, failure cause or present plant state.
6. Preserve reported failure windows and maintenance notes as attributed records. A report entry is not a
   verified work-order closure, executed configuration or successful repair. Retain missing timezone, action,
   asset/work-order identity and effectiveness evidence as explicit collection needs.
7. Give the engineer concrete collection prompts and a decision rule for each unresolved question. Use the
   existing question/context formats; do not add a competing question engine or import route. All supplied
   responses remain AI-authored proposals, without owners, assignments, reviewers, acceptance or plant-truth
   confirmation. Current source fingerprints do not confer authority.
8. Exercise the actual prepare/apply CLIs and retained-register refresh. Independently revising copied PDF/CSV
   sources makes exactly their dependent answers stale, preserving all decision history and unrelated answers.
   Stale answer resubmission and missing originals refuse without changing the destination. Repetition is
   byte-identical. Synthetic revisions are labelled software controls, not new operational events.
9. Commit a small readable expected report and bound proposals/key. Registered offline checks validate their
   structure and joins; original-source checks require the cached originals and visibly skip when absent.
   Do not substitute a committed transcription for an original-source verification or fetch during a test.
10. Obtain independent primary-source and software checks plus a fresh reader run of the instructions. Report
    failures, the exact evidence scope and any remaining omissions. No timed human review, live connector,
    causality, savings, native import or customer/adoption claim follows from this packet.
